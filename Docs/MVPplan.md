# MVP: каталог мебели с необязательным AR

## Цель и границы

Android-приложение для обычных телефонов. Каталог, карточка товара, корзина и демонстрационное оформление работают без ARCore. AR доступен только на поддерживаемых устройствах. Планшеты в MVP не тестируются.

- Unity 6, AR Foundation, ARCore, C#; локальные данные, без бэкенда.
- 6 товаров: по 2 кресла, стола и дивана. Изображения и модели подбираются в Unity Asset Store и включаются в приложение.
- Один цвет и один материал на товар: это свойства для отображения и фильтрации, без переключения вариантов.
- Интерфейс на русском, цены в рублях. Визуальный ориентир: светлый фон, округлые карточки, крупное изображение товара, компактная панель в AR.
- Оплата демонстрационная: без банковских данных и реальных транзакций.

## Пользовательский путь

Каталог → карточка товара → при поддержке устройства просмотр в AR → корзина → демонстрационный экран оформления.

Если AR недоступен, каталог, карточка, корзина и оформление продолжают работать; кнопка AR объясняет причину недоступности.

## Подробные шаги разработки

### 1. Подготовить Android-сборку

1. Установить через Unity Hub Android Build Support с SDK/NDK/OpenJDK и переключить платформу проекта на Android.
2. Создать стартовую сцену каталога без AR-компонентов. Существующую `MainScene` использовать как сцену AR. Включить обе сцены в Build Profiles, каталог поставить первым.
3. В XR Plug-in Management проверить, что ARCore включён для Android, Requirement = Optional, Depth = Optional; пройти Android Project Validation.
4. В Player Settings проверить Minimum API Level (сейчас 25), выбрать IL2CPP и включить ARM64, сохранив ARMv7 для совместимых 32-битных телефонов. Собрать и открыть пустой каталог на телефоне.

**Готово:** приложение устанавливается, открывает каталог и не запрашивает доступ к камере при обычном просмотре.

### 2. Подготовить шесть товаров

1. Выбрать по две модели кресел, столов и диванов из Unity Asset Store. Для ранней проверки AR можно использовать один временный объект, не ожидая всех моделей.
2. Для каждого товара определить ID, название, цену в рублях, описание, категорию, ширину/высоту/глубину в сантиметрах, один цвет, один материал, изображение и prefab модели.
3. Импортировать только нужные для товаров файлы. Проверить внешний вид на мобильном рендерере, единицы масштаба (1 единица Unity = 1 метр) и точку установки модели на полу. Габариты в карточке должны соответствовать модели.
4. Хранить шесть записей в одном локальном каталоге Unity со ссылками на изображения и prefabs. Сервер, загрузка товаров во время работы и система вариантов не нужны.

**Готово:** список из шести товаров открывается без сети; каждый товар имеет корректные данные, изображение и модель.

### 3. Сделать каталог и карточку товара

1. В стартовой сцене собрать интерфейс средствами установленного uGUI: прокручиваемый список, карточки, панель фильтров, экран товара. Использовать светлый фон, округлые белые карточки, крупное изображение, русские подписи и цены в ₽. Проверить читаемость на обычных экранах телефонов и безопасные отступы у вырезов экрана.
2. Выводить в карточке название, цену, изображение и основные свойства; на экране товара — полное описание и точные габариты.
3. Реализовать фильтры: категория; цена «от–до»; верхние пределы ширины, высоты и глубины в сантиметрах; цвет; материал. Применять все заданные условия одновременно. Добавить сброс и сообщение «Ничего не найдено».
4. Связать выбранный товар с кнопками «Посмотреть в AR» и «В корзину». Обычный просмотр товара и покупательский путь доступны независимо от AR.

**Готово:** все шесть товаров отображаются; сочетания фильтров, сброс и пустой результат работают; карточка открывает нужный товар.

### 4. Подключать AR только при поддержке

1. При нажатии «Посмотреть в AR» проверить `ARSession.state`; при неизвестной доступности вызвать `ARSession.CheckAvailability()`. Обработать `Unsupported` сообщением, `NeedsInstall` предложением `ARSession.Install()`, а при готовности открыть AR-сцену. Пока идёт проверка или установка, показать состояние ожидания; при неудаче вернуться к товару.
2. Не запускать AR-сессию из стартовой сцены. Если пользователь отклонил установку сервиса или доступ к камере, оставить каталог и корзину рабочими.
3. В AR-сцене использовать уже имеющиеся `AR Session`, `XR Origin` и камеру. При выходе останавливать AR-сессию и возвращать пользователя к выбранному товару.
4. Проверить этот путь на ARCore-телефоне и на телефоне без ARCore. Значение Optional в настройках не заменяет проверку во время работы.

**Готово:** неподдерживаемый телефон пользуется приложением без AR; поддерживаемый входит в AR после необходимых разрешений и установки сервиса.

### 5. Разместить мебель и добавить жесты

1. Добавить к `XR Origin` компоненты `ARPlaneManager` с горизонтальными плоскостями и `ARRaycastManager`. При отсутствии плоскости показывать подсказку «Наведите камеру на пол».
2. По касанию найденной плоскости разместить prefab выбранного товара один раз. Использовать исходный масштаб модели: пользователь видит реальные габариты.
3. Одним пальцем перемещать предмет по найденной плоскости, жестом двух пальцев поворачивать вокруг вертикальной оси. Масштабирование отключить. Касания кнопок интерфейса игнорировать в обработке жестов.
4. Показать в AR название, цену, кнопку добавления в корзину и выход. Если слежение временно потеряно, показать сообщение и не двигать модель до восстановления.

**Готово:** выбранная мебель стоит на полу в верном размере, перемещается и поворачивается; одновременно существует только один предмет.

### 6. Сделать корзину и демонстрационную оплату

1. Хранить в текущем сеансе ID товара и количество; повторное добавление увеличивает количество. В корзине показывать товары, цену, количество и итог. Изменение количества и удаление сразу меняют сумму.
2. Сделать экран оформления в стиле каталога: состав заказа, сумма и кнопка демонстрационного подтверждения. После подтверждения показать экран успеха. Не запрашивать номер карты и не обращаться к платёжному сервису.
3. Проверить добавление как с карточки товара, так и из AR. При возврате из AR корзина и выбранный товар сохраняются.

**Готово:** оба пути добавления дают одинаковую корзину и итог; демонстрационное оформление завершается без транзакции.

### 7. Проверить MVP целиком

1. В редакторе проверить фильтрацию и расчёт суммы небольшими автоматическими проверками; UI и навигацию пройти вручную.
2. На телефоне с ARCore пройти полный путь: каталог → фильтры → товар → AR → перемещение/поворот → корзина → оформление. Depth API для этого теста не требуется.
3. На телефоне без ARCore пройти каталог, фильтры, карточку, корзину и оформление; убедиться, что AR не запускается. Отдельно проверить отказ в разрешении камеры и установке AR-сервиса.
4. Собрать финальный APK, проверить отсутствие ошибок при запуске и открыть все шесть моделей на телефоне.

**Готово:** оба сценария проходят на реальных телефонах; ошибок, блокирующих пользовательский путь, нет.

## Текущее состояние проекта

AR Foundation и ARCore установлены; настройки ARCore и Depth — Optional. Каталог, товары и управление размещением ещё не реализованы. Текущий минимум Android — API 25; поддержка более старых версий в MVP не заявлена.

## За пределами MVP

Бэкенд, настоящая оплата, аккаунты, смена цвета или материала модели, несколько предметов одновременно, масштабирование жестом, Depth-окклюзия, снимки камеры, ручное управление освещением и тестирование планшетов.
