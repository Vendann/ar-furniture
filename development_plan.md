# План разработки AR Furniture MVP

## Цель MVP

Android-приложение на Unity 6, в котором пользователь проходит сценарий:

`Каталог → товар → просмотр в AR → оформление`

В MVP входят:

- локальный каталог из шести предметов мебели;
- фильтрация по категории и максимальной цене;
- просмотр выбранного товара;
- размещение, перемещение и поворот одного предмета в AR;
- демонстрационная форма оформления без настоящей оплаты.

## Техническая основа

- Unity `6000.3.24f1`;
- Universal Render Pipeline;
- AR Foundation и ARCore;
- Input System;
- uGUI;
- Android, портретная ориентация;
- одна сцена `MainScene` с переключаемыми UI-панелями;
- локальные данные без backend, API и базы данных;
- новые пакеты не требуются.

## Порядок feature-веток

Разработка выполняется последовательно, поскольку все части изменяют `MainScene` и используют выбранный товар:

```text
main
 └─ feature/base-catalog → main
     └─ feature/ar-placement → main
         └─ feature/checkout → main
```

Каждая следующая ветка создаётся от обновлённой `main` после слияния предыдущей. Отдельные ветки для UI, тестов, навигации и Android-сборки не нужны: это части соответствующих features.

## 1. `feature/base-catalog`

### Данные каталога

- Создать один `ProductCatalog` в формате `ScriptableObject`.
- Добавить шесть существующих товаров из `Assets/AR-Furniture/Prefabs`.
- Для каждого товара хранить:
  - название;
  - категорию;
  - цену в рублях;
  - изображение из `Assets/AR-Furniture/Images/ProductCards`;
  - prefab для AR.
- Использовать категории `Диваны`, `Кресла`, `Столы`.
- Назначить разные произвольные цены, чтобы фильтр можно было проверить.

### Каталог

- Создать прокручиваемый список карточек.
- Показывать на карточке изображение, название и цену.
- Добавить кнопки `Все`, `Диваны`, `Кресла`, `Столы`.
- Добавить ползунок `Цена до`.
- Одновременно применять фильтр категории и цены.
- По нажатию на карточку открывать панель выбранного товара.

### Панель товара

- Показывать изображение, название и цену.
- Добавить кнопки `Посмотреть в AR` и `Оформить`.
- Добавить возврат в каталог.
- Хранить выбранный товар только в памяти текущего запуска.

### Проверка ветки

- Все шесть товаров отображаются.
- Категории и цена фильтруют список совместно.
- Карточка открывает правильный товар.
- Добавлен один EditMode-тест логики фильтрации.
- Сцена запускается без ошибок.

## 2. `feature/ar-placement`

Ветка создаётся после слияния `feature/base-catalog`.

### Настройка AR

- Использовать существующие `AR Session` и `XR Origin` в `MainScene`.
- Добавить `ARPlaneManager` и `ARRaycastManager`.
- Настроить обнаружение горизонтальных плоскостей.
- Добавить простую визуализацию плоскостей и оставлять её видимой после размещения.

### Взаимодействие с мебелью

- При первом касании плоскости создать prefab выбранного товара.
- Не создавать второй предмет, пока первый уже размещён.
- Перемещать предмет по горизонтальной плоскости перетаскиванием одним пальцем.
- Поворачивать предмет жестом двух пальцев.
- Сохранять исходный масштаб prefab; масштабирование жестами не добавлять.
- Добавить возврат на панель товара.

### Android

- Установить портретную ориентацию.
- Проверить настройки ARCore и Android Player Settings.
- Подготовить Android-сборку.

### Проверка ветки

- XR Simulation обнаруживает и визуализирует горизонтальную плоскость.
- Выбранная модель размещается касанием.
- В сцене одновременно находится только один предмет.
- Перемещение и поворот работают в симуляции.
- Масштаб модели не изменяется.
- Android-сборка создаётся без ошибок.

Полноценная проверка камеры, распознавания пола и жестов на устройстве откладывается до появления ARCore-совместимого Android-устройства.

## 3. `feature/checkout`

Ветка создаётся после слияния `feature/ar-placement`.

### Форма оформления

- Показывать выбранный товар и его цену.
- Добавить поля:
  - имя;
  - телефон;
  - адрес;
  - номер карты;
  - срок действия;
  - CVV.
- Проверять заполнение обязательных полей.
- По кнопке `Оплатить` показывать экран успешного оформления.
- Добавить возврат к товару или каталогу.
- Не отправлять и не сохранять введённые данные.

### Проверка ветки

- В оформлении отображается правильный товар.
- Пустые обязательные поля не позволяют завершить оформление.
- Заполненная форма открывает экран успеха.
- Переходы назад не теряют выбранный товар.
- В приложении отсутствуют сетевые запросы и настоящая транзакция.

## Итоговая проверка после слияния

- Пройти полный сценарий `Каталог → товар → AR → товар → оформление → успех`.
- Проверить фильтры на всех шести товарах.
- Проверить интерфейс в портретной ориентации.
- Запустить EditMode-тест фильтрации.
- Проверить AR через XR Simulation.
- Собрать Android-приложение без ошибок.

## Не входит в MVP

- backend и сетевой каталог;
- регистрация и авторизация;
- корзина и покупка нескольких товаров;
- настоящая платёжная система;
- хранение платёжных или пользовательских данных;
- масштабирование мебели;
- несколько предметов в AR;
- вертикальные поверхности;
- избранное;
- аналитика;
- дополнительный визуальный полиш.
